Security scanners for AI agent skills and MCP servers claim to find prompt injection, secret exfiltration and
poisoned tools. Rantanplan asks the reverse question: **can the scanner be made to judge incorrectly?**

- Does rewording, splitting an instruction across files, or hiding it in Unicode or base64 make an attack disappear?
- Does harmless defensive text ("Never send API keys ...") trigger a false alarm?
- Is every "miss" a real miss, or did the mutation silently change the meaning? A **metamorphic oracle** decides.

```text
$ rantanplan compare
 Metric                       mock-blind   mock-paranoid   mock-naive   mock-strict
 Grade                        F 0.00       D 0.54          F 0.42       A+ 1.00
 Recall (attacks detected)    0%           94%             42%          100%
 Specificity (benign passed)  100%         54%             93%          100%
 Obfuscation robustness       n/a          67%             60%          100%
```

On a real binary, SKIL v0.6.0 scores **B** (recall 81%, specificity 85%, strong against Unicode/encoding tricks, weak on
instructions split across sections or files): [full report](docs/benchmarks/skil-v0.6.0.md).
Alpha software: read [what the score does not tell you](docs/LIMITATIONS.md).

## 💡 What is Rantanplan?

Rantanplan evaluates static security scanners for AI agent skills and MCP servers through **Metamorphic Testing** (oracle-checked, seeded mutation of attack and benign cases).

### Product Differentiation

| Tool | Focus | Question Answered |
| :--- | :--- | :--- |
| **SKIL** | Skill Governance & Trust | *Can this agent skill be trusted in production?* |
| **SkillSpector** | Static Skill Inspection | *Does this skill contain known rule violations?* |
| **garak** | LLM Vulnerability Scanning | *Can this model/agent be jailbroken?* |
| **SkillEvaluator** | Skill Benchmarking | *Does this skill improve task performance?* |
| **Rantanplan** | **Control Assurance** | ***Can the systems making those judgments be made to judge incorrectly?*** |

## ⚙️ How It Works

```text
Corpus (independent labels) ──► 8 mutators (seeded) ──► Metamorphic oracle ──► Target (sandboxed subprocess)
                                                         │ rejects drift                │
                                                         ▼                              ▼
                                                  counted, never scored        Verdict per run ──► Score card + grade
```

1. **Corpus**: about 100 clean-room cases (`corpus/`, generated by `rantanplan corpus build`) plus
   hand-written cases (`cases/`) across five domains: secret exfiltration, prompt injection, code
   execution, obfuscation and MCP tool poisoning. Each has an independently written malicious/benign
   label, including ~40 hard negatives (defensive text such as "Never send API keys ...").
2. **Eight mutators**, all driven by `--seed` so runs are reproducible:
   **lexical** (synonyms), **semantic** (maintenance/diagnostic framing), **split_instruction**
   (steps across sections), **cross_file** (chain across `SKILL.md` and `references/reporting.md`),
   **code_alias** (`getattr` dispatch, aliasing), **unicode** (zero-width, homoglyphs, BIDI isolates),
   **encoding** (base64 notes, split string literals) and **negative_context** (defensive wording:
   a hard negative on benign text, *camouflage* on an attack).
3. **Metamorphic oracle**: a mutant is only scored if a transparent reference analysis shows its label,
   capability signals and literal indicators (hosts, commands) are unchanged. Rejected mutants are
   counted and reported ([ADR 0003](docs/adr/0003-metamorphic-oracle.md)).
4. **Sandboxed execution**: no shell, process-group timeout, sanitised environment, temp workspace.
   A crash, silence or unparsable output is `INCOMPLETE`, never a detection or a pass.
5. **Score card**: recall, specificity, four robustness metrics and negative-context safety, each with
   `n` and a Wilson 95% interval; geometric mean capped by the weaker of recall/specificity; grade
   A+ to F, or `INCOMPLETE` / low confidence when the evidence is thin ([SCORING.md](docs/SCORING.md)).

> **Status (v0.2.0).** The scale is calibrated on four built-in targets
> ([REFERENCE_BENCHMARK.md](docs/REFERENCE_BENCHMARK.md)). Only **SKIL v0.6.0** has been scored on a real binary ([result](docs/benchmarks/skil-v0.6.0.md): grade B, recall 81%, specificity 85%, weak on split-instruction and cross-file attacks); see
> [docs/LIMITATIONS.md](docs/LIMITATIONS.md) before relying on a grade. Evaluator and agent-chaos
> assurance are not implemented.

## 🚀 Quick Start & Installation

### Prerequisites
- Python 3.12+ and [uv](https://docs.astral.sh/uv/) (or pip)
- Optional: the scanner binaries you want to test (`skil`, `skillspector`, `garak`, ...). Missing binaries are reported as `INCOMPLETE`, not as a pass.

### Install

```bash
git clone https://github.com/domehahn/rantanplan.git
cd rantanplan
uv sync --extra dev
uv run rantanplan --help
```

### Verify

```bash
uv run rantanplan doctor          # scanner binaries and versions
uv run rantanplan verify-ground-truth
uv run pytest
```

## 🛠️ Command Reference

| Command | Purpose |
| :--- | :--- |
| `test scanner --target T [--seed N] [--format dashboard\|json\|markdown\|html] [--output F]` | Score one target with oracle-approved mutation |
| `compare --targets a,b,c` | Score several targets on identical mutants |
| `mutate --case ID` | Show every mutant of a case with the oracle's verdict |
| `hunt --target T --mode false-negative\|false-positive` | Adaptive search (chains of mutations) for evasions / false positives |
| `minimize --target T --case ID` | ddmin to a minimal reproducer that keeps outcome and label |
| `gate --results F --min-grade B` | CI gate on a JSON result (rejects `INCOMPLETE` and low confidence) |
| `export regression --target T` | Write each evasion found as a standalone regression case |
| `corpus build` / `corpus list` / `verify-ground-truth` | Generate, inspect and verify the corpus |
| `suite offline-core` / `benchmark` | Calibrate the scale / regenerate the reference benchmark |
| `doctor`, `list`, `gaps`, `inventory`, `upstream check`, `demo` | Environment and ecosystem diagnostics |

Built-in calibration targets: `mock-blind`, `mock-paranoid`, `mock-naive`, `mock-strict`.
See [docs/CLI_REFERENCE.md](docs/CLI_REFERENCE.md).

```bash
uv run rantanplan test scanner --target mock-naive           # weak keyword scanner: F
uv run rantanplan compare                                    # the four calibration targets
uv run rantanplan test scanner --target skil --format json --output skil.json
uv run rantanplan gate --results skil.json --min-grade B
```

## 🎯 Testing Against SKIL

1. Install the `skil` binary and make sure it is on your `PATH` (or set `RANTANPLAN_SKIL_BIN`).
2. Run:

```bash
uv run rantanplan doctor
uv run rantanplan test scanner --target skil --format markdown --output skil.md
uv run rantanplan hunt --target skil --mode false-negative
```

## 🔒 Security & Threat Model

- **Fixtures as data**: untrusted test case content is written to temp directories and passed to scanners, never executed directly.
- **No shell execution**: subprocesses are launched with explicit `argv` (`shell=False`).
- **Resource limits**: timeouts and sanitized environment.

See [docs/THREAT_MODEL.md](docs/THREAT_MODEL.md).
